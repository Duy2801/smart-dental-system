# Smart Dental System — Architecture Diagram

Sơ đồ tổng quan dựa trên code hiện tại: ba ứng dụng giao diện, backend NestJS dùng chung, PostgreSQL, Redis và dịch vụ AI FastAPI chạy riêng. Các nhóm chức năng bên trong backend không phải microservice độc lập.

## Cách copy vào draw.io

1. Mở [app.diagrams.net](https://app.diagrams.net/) và tạo **Blank Diagram**.
2. Chọn **Extras → Edit Diagram**.
3. Xóa XML đang có, copy **toàn bộ nội dung bên trong khối XML bên dưới** và dán vào. Không copy hai dòng dấu ```.
4. Chọn **Replace existing drawing** nếu có lựa chọn này, rồi nhấn **OK / Apply**.
5. Chọn **View → Zoom → Fit Window** để xem toàn bộ hình. Mỗi khối và đường nối đều có thể chỉnh riêng.

Thao tác XML theo [hướng dẫn chính thức của draw.io](https://www.drawio.com/docs/manual/advanced/diagram-source-edit/).

## Cách đọc và phạm vi

- Giao diện gọi REST API và kết nối Socket.IO đến backend NestJS. Nhãn ở mỗi ứng dụng gom các kết nối; không phải mọi vai trò đều dùng mọi tính năng realtime.
- Backend quản lý xác thực, phân quyền, dữ liệu và nghiệp vụ. Các chức năng trong khối NestJS là những module của cùng một ứng dụng.
- PostgreSQL lưu dữ liệu nghiệp vụ qua Prisma. Redis phục vụ cache, token, OTP và hàng đợi email Bull; Mail Worker chạy trong ứng dụng backend.
- Backend gọi FastAPI để xử lý AI. Booking Agent trong FastAPI cũng gọi API backend để tra cứu và tạo lịch hẹn; mũi tên hai đầu gom hai loại lời gọi này.
- RAG dùng kho `knowledge.jsonl` và tìm theo từ khóa. Model YOLO / DeepLab chạy local trong tiến trình AI; LLM bên ngoài sinh nội dung và diễn giải kết quả.
- Khối tích hợp gom nhiều dịch vụ: backend upload lên Cloudinary, gửi email qua SMTP, nhận webhook từ SePay và tạo URL phòng Jitsi. Client tham gia video trực tiếp qua Jitsi.
- Bản tổng quan lược bỏ các luồng phụ như Google Login, CAPTCHA, truy cập URL ảnh và fallback chatbot gọi thẳng AI từ mobile để giữ hình dễ đọc. Sơ đồ thể hiện kiến trúc logic, không thể hiện máy chủ triển khai thực tế.
